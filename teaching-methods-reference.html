教學方法參考

這個 repo 的設計依據：國際實證研究與方法

本 repo 的教材編排、PR 提交機制、AI 審查設計，不是憑空想像，而是參考了以下國際上已有實證基礎的方法。整理這頁的目的，是讓有興趣參考這套做法的老師，能同時看到「我們做了什麼」跟「這麼做的依據是什麼」，方便評估是否適合自己的課程。

Feedback Pull Requests（GitHub Classroom）

來源：GitHub Education 官方文件

GitHub 為教學情境設計的內建機制：學生接受作業後，系統自動開一個 PR 供老師逐行留言回饋，並內建「GitHub 帳號 ↔ 真實姓名」花名冊對應功能。

💡 本 repo 對應：我們的 PR 提交流程是手動搭建的簡化版，若未來要擴大規模，GitHub Classroom 的花名冊功能可以取代目前手動維護對照表的做法。

🔗 docs.github.com（GitHub Classroom 官方文件）

Git-based 作業提交系統的實測效益

來源：Improving Assignment Submission in Higher Education through a Git-Enabled System: An Iterative Case Study（2025，arXiv）

研究實測比較 Git 版本紀錄批改 vs. 傳統批改，發現利用 commit 歷程批改可節省約 38% 的批改時間，並能透過 commit 時間戳記識別最後一刻趕工的提交、比對版本歷程協助判斷是否為抄襲。

💡 本 repo 對應：我們用 PR 的 commit 歷程跟 Actions 排程審查，方向與此研究一致；commit 時間分布這個資料維度目前還沒有利用，是可以擴充的方向。

🔗 arxiv.org/html/2510.06363

Case Method 教學創新的系統性回顧（2000–2024）

來源：Innovations in the case method of teaching management, 2000–2024: A scoping review（ScienceDirect, 2025）

分析 84 篇案例教學創新論文，歸納出五大驅動力：課堂管理困難、傳統教材不足、學生參與度不足、課程設計挑戰、線上教學挑戰。

💡 本 repo 對應：解決「傳統教材不足」（改用真實新聞案例而非死板判決書）與「學生參與度不足」（用 PR 互動取代單向繳交）這兩項，是這個 repo 最初的設計動機。

🔗 sciencedirect.com/science/article/pii/S1472811725000205

結構化任務提升案例教學學習效果

來源：The efficacy of the case method in tertiary business education: A scoping review: 2000-2022（ScienceDirect, 2024）

回顧研究指出：案例任務的結構化程度越高（給予明確的分析架構與引導），學生在知識掌握、批判思考、課堂參與、團隊合作、決策能力等面向的學習效果越好。

💡 本 repo 對應：講義框架裡的「引導提問」「範例句型」「補完步驟建議」「進度統計」，都是把這個結構化原則落實成具體介面設計。

🔗 sciencedirect.com/science/article/pii/S1472811724000545

Role-play 作為正式的案例教學類型

來源：National Center for Case Study Teaching in Science, SUNY-Buffalo（案例類型與教學方法分類）

該機構把案例教學的「方法」正式分類為 PBL、辯論、jigsaw 拼圖法、role-play（角色扮演）、公聽會模擬等類型，role-play 是其中被廣泛採用、有教學實績的正式類型之一。

💡 本 repo 對應：「換你當事人」這個區塊（要求學生假設自己是案例中某一方的決策者，提出自己的策略），採用的就是 role-play 這個正式教學類型，不是隨意設計的花招。

🔗 sciencecases.lib.buffalo.edu（經 Columbia CTL 案例教學資源頁引用確認）

另外查到 TaBLE Case Method（結合課前個人準備與課堂小組討論的五階段案例教學法，2024年發表於澳洲大學的實證研究）也是有實證基礎的方法，但因為不希望在這個 repo 裡加入小組協作的環節，這次沒有採用，僅記錄於此供未來參考。
